# Topological Naming

## The problem

OCCT regenerates topology on every modeling operation. "Face 3" of one result
has no guaranteed relationship to "face 3" of the next — or even to the same
feature recomputed after an upstream edit. A history that stores raw indices
("push face 3 by 15 mm") silently applies later steps to the wrong geometry
when anything upstream changes. This is the classic *topological naming
problem* (FreeCAD's long-running TNP, fixed properly only in 1.0 via an
element-map of operation provenance).

## What OpenShape does now (interim, implemented)

A persistent reference (`doc::FaceRef`, `doc::EdgeRef`) stores:

1. an **index hint** — the topology index when the reference was made, and
2. a **geometric signature** (`geom::FaceSignature` / `EdgeSignature`):
   - face: surface kind, outward normal, area centroid, area;
   - edge: curve kind, midpoint, unit tangent, length.

Resolution (`geom::resolveFace` / `resolveEdge`):

1. If the hinted index still matches the signature *exactly* (within 1e-6
   relative), use it. This is the common case: nothing upstream changed.
2. Otherwise score every candidate of the same kind (planar faces must have the
   same normal): centroid distance normalized by part size, plus relative
   area/length difference. Take the best.
3. If the best score is implausible, **fail**: the feature is marked `Failed`
   with "The face this operation was applied to no longer exists." The history
   is preserved and the user can fix the upstream edit.

Selections use the same signatures, so the face you just pushed stays selected
after the commit, and selections survive undo/redo where the face still exists.

**Known weaknesses:** symmetric parts (several faces with the same normal and
area) can resolve to the wrong one after large upstream moves; large moves of
the referenced face relative to the part size fail rather than follow. Both
fail *visibly* (wrong face is at least the same kind and orientation;
unresolvable references mark the feature failed).

## Where this is going (planned)

A hybrid of **operation provenance** and signatures:

- Use OCCT's history APIs (`BRepAlgoAPI_*::Modified/Generated/IsDeleted`,
  `BRepTools_History`, `BRepFilletAPI_MakeFillet::Generated`) to record, per
  feature, how each output face/edge derives from input faces/edges and from
  the feature's own entities (e.g. "the cap face generated by PushPull X",
  "side face generated from edge E of the pushed face").
- Name topology by that provenance path (similar to FreeCAD's element map /
  Onshape's persistent ids), keeping the geometric signature as a tie-breaker
  and validation check.
- Sketch-based features (M1+) name faces by the sketch entity that generated
  them ("face swept from line L of Sketch S"), which is stable by construction.

Trigger to start: Milestone 4 (editable history), when upstream edits become a
routine user action rather than an edge case.
